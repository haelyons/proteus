# A first read of one unit

I interpret “first read” as a human opening one unit, looking through a small set of complementary views, writing a provisional explanation and a rival, making one prediction before seeing its result, and recording what changed. It is an observation and criticism notebook, not an automated labeller, a cleanliness score, or a completed mechanistic investigation. A successful session may end with “cannot tell”. This follows [ANSWERS §0 and §1.4](../ANSWERS.md:6), [§3.5](../ANSWERS.md:169), and the owner's [prediction discipline](../BRIEF.md:36).

The essay says the shared shape became apparent in the familiar grid, then wiring confirmed it; Janus found that changing the comparison often mattered more than changing the prompt. Those are different claims. The notebook should let a reader inspect both without announcing either as truth. See [essay lines 83–89](../../janus/authors/informed.prompt_sent.md:83), [ANSWERS lines 8–20](../ANSWERS.md:8), and [PREDICTIONS, scored failures](../PREDICTIONS.md:108).

## What it responds to versus how it is wired

R2–R8 are response evidence. **R9 is a separate wiring view:** signed input weights, data-weighted input contributions, downstream readers and their renders. Weight strength and contribution on data must retain separate rankings. The strongest reader must not be mistaken for an input. See [ANSWERS:47](../ANSWERS.md:47), [BRIEF:22](../BRIEF.md:22), [README circuit and renders:105](../../janus/README.md:105), and [essay:477](../../janus/authors/informed.prompt_sent.md:477).

For 55, `runs/circuit/circuit.npz` supplies the 528 signed input weights, bias, and per-photo contributions at the target hotspot. `runs/featvis/renders.jpg` supplies the target, six positive and two negative inputs, and three positive readers in mixed5a's 1×1 branch, annotated with weights. This is a partial reader view, not all outgoing paths. It does not measure downstream causal use. There is no corresponding cache for 431 in these tools. Show that gap. General wiring, output suppressors, reader ablations and weight-based families remain follow-up work; neither the notebook nor the existing renders establishes a mechanism.

## What it must record

**R10. Preserve a reading that can lose.** Before revealing transformation results, record reader identity, prior exposure, observed response, evidence references, rival explanation, confidence, and a predicted retention interval and layer-relative category for one chosen transformation. Save the exact unit, source fingerprints, rule and timestamp with the prediction. Then reveal the measured result and save a separate outcome. Finally record a revised response explanation, a separate wiring interpretation, family distinction, failures, missing evidence, next discriminating test, and provisional class (`one`, `one_plus_related`, `unrelated`, `cannot_tell`). The original prediction must remain unchanged. This follows [CONTRACT:20](../../janus/CONTRACT.md:20), [BRIEF:38](../BRIEF.md:38), [essay:649](../../janus/authors/informed.prompt_sent.md:649), and [OBSERVATIONS D4:222](../OBSERVATIONS.md:222). No existing Janus tool provides this interactive journal.

“Commit” here means an exclusive-create local JSON record and SHA-256 digest, not a Git commit or an independently witnessed preregistration. Cached outcomes already exist and unit identities are visible. Older card/holdout and D/T splits overlap. Record prior exposure and call this **prediction-before-reveal replay**, not a blind experiment. A matched interval tests that prediction only; it cannot decide whether the unit has one job. [CONTRACT:43](../../janus/CONTRACT.md:43) explicitly gives 55 no truth class, and [PREDICTIONS:85](../PREDICTIONS.md:85) rejects predictive success as sufficient acceptance.

## Acceptance

**R11. Small, local and inspectable.** Open with the requested marimo command; execute as a script for both units; opening or rerunning cells must not save a reading or run inference. Only explicit form submission writes journal records under this directory. Missing views say “unavailable”, never zero or pass. Report checks in `NOTES.md`. This implements the task boundaries and [ANSWERS §2.3–2.4](../ANSWERS.md:104), [§5.2](../ANSWERS.md:224): reuse the standing measurements and leave new hypothesis-dependent work for later.
